Objective
Extend the existing Department Workspace so an authorized department user can maintain the department's DGLP MMF and ECHS MMF quantities for its ACTIVE canonical-item assignments.
MMF means Monthly Maintenance Figure: the expected monthly quantity/requirement.
DGLP and ECHS are the two budget heads. PVMS and NIV are identifiers only and must never be treated as budget heads.
Required behaviour
For each ACTIVE department assignment:
Display current DGLP MMF.
Display current ECHS MMF.
Allow editing each independently.
Accept valid non-negative numeric quantities appropriate to the existing data model.
Reject malformed, negative, or otherwise invalid values server-side.
Save through a proper API endpoint.
Reloading the workspace must show the persisted values.
Editing DGLP must not alter ECHS, and vice versa.
Department A must never be able to modify Department B's MMF.
REMOVED assignments must not be editable.
Do not invent a new conceptual budget structure. There are exactly two MMF quantities: DGLP and ECHS.
Data model / history
Inspect the existing implementation only where necessary to determine the correct persistence model.
MMF values are departmental values associated with the department/canonical-item relationship. Do not put department-specific MMF into the global canonical item itself.
If the existing schema already provides appropriate revision/history support, use it.
If it does not, implement the minimum necessary MMF revision/history model so that consequential MMF changes are traceable. At minimum preserve:

previous value/new value where appropriate
