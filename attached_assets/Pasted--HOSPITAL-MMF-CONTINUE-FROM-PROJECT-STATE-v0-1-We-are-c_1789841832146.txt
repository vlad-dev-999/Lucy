============================================================

============================================================
4. CANONICAL ITEM MODEL
============================================================

Introduce the internal:

CANONICAL ITEM ID

This must be independent of:

- PVMS
- NIV
- legacy row number
- nomenclature

Example:

CAN-000001

The Canonical Item ID is the application's stable identity for an item.

PVMS and NIV remain attributes/identifiers associated with the item.

Never use PVMS or NIV as the primary key.

============================================================
5. LEGACY → CANONICAL LINEAGE
============================================================

Create explicit lineage between legacy records and canonical items.

Conceptually:

Legacy Record
      ↓
Canonical Item

and potentially:

Legacy Record A
Legacy Record B
      ↓
Canonical Item CAN-001234

The lineage must preserve the original records.

Do not delete legacy records when merging them into a canonical item.

Do not silently merge records.

============================================================
9. IMPORTANT BUSINESS RULES
============================================================

Do not break these:

PVMS/NIV are identifiers.

DGLP/ECHS are the only budget heads.

Blank PVMS/NIV is legitimate legacy data and is a warning.

Canonical Item ID is independent of PVMS/NIV.

Legacy data is immutable.

Similar nomenclature does not prove clinical equivalence.

Matching identifiers does not prove clinical equivalence.

Never silently merge.

Never silently delete.

Department removal later must not delete the canonical item.
